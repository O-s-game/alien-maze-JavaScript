# 迷路脱出ゲーム：自律分散型学習AI（プロトタイプ）

JavaScriptを用いて、アルゴリズムの設計からデバッグまでを完全独学で実装した迷路ゲームです。
特に敵キャラクター（Alien）の思考ルーチンにおいて、段階的なAIの発展と、失敗を記憶する学習機能の構築に注力しました。

### 💡 開発の動機（参考書のカスタマイズ）
ベースとなる参考書のサンプルゲームを実際にプレイした際、「敵が壁を貫通して追いかけてくる」「動きが単調で理不尽に難易度が高い」という仕様に不満と課題を感じました。
そこで、「プレイヤーにとってより面白く、論理的な動きをする敵AIに改造したい」という目的を持ち、独自のアルゴリズム（壁判定・優先順位・失敗記憶）を設計・実装しました。


## 🚀 本作のこだわりと技術的アピールポイント

### 1. 段階的なAI思考ルーチンの発展
一から複雑なコードを組むのではなく、バグを抑え論理を破綻させないために段階的なフェーズに分けてAIを発展させました。
* **Lv.1：基本の壁回避**
  キャラクターが障害物を認識し、壁をすり抜けない正確な当たり判定を実装。
* **Lv.2：優先順位に基づく方向判断**
  「前 ＞ 右 ＞ 左 ＞ 後ろ」の優先順位をアルゴリズムとして設定。無秩序なランダム移動ではなく、一定の判断基準を持った追跡行動を実装。
* **Lv.3：失敗経験の記憶と学習**
  行き止まりに進入したマスの座標を記憶させ、同じマスに到達した際に過去の失敗経験を参照してルートを回避する学習機能を設計。

### 2. 「設計ファースト」による論理的な開発プロセス
いきなりコードを書き始めるのではなく、まずは日本語で「AIが何を判断し、何をいつ記憶し、どこでそのデータを使うか」というロジックを設計してから実装に移りました。「コードを書くこと」以上に「アルゴリズムを設計すること」を重視しています。

### 3. 二段階の記憶保存システムによる「意図と結果」の分離
「進もうとした予測」と「実際に起きた結果」を混同させないため、失敗経験の記録を二段階に分離しました。
* 方向の決定 ➔ `memo`（一時的な下書き）への仮置き ➔ 実際の探索・判定 ➔ 「本当に行き止まりだった」と確定した段階で初めて `failMemory`（正式保存）へ移行。

### 4. 記憶データ構造の責務分離（関心の分離）
単一のメモリに情報を詰め込むのを避け、用途ごとに役割を明確に切り分け、プログラムの肥大化やスパゲティコード化を防いでいます。
* `memo`：方向決定時の一時的な下書き・推論用バッファ
* `failMemory`：過去の失敗経験を保持する長期記憶（学習データ）
* `route`：行き止まりから安全に戻るための一時的な探索・復帰ルート
* 各種関数（`Think()` / `avoidWall()` / `doScroll()`）による役割の明確な分離

### 5. 複数AIの独立した自律分散設計（インスタンスごとの個別学習）
失敗経験（`failMemory`）を全AIで共有せず、エイリアン（Alien）個体がそれぞれのインスタンスとして独立して管理する設計にしました。「経験はそのAI自身のもの」という思想に基づき、個体ごとに異なる自律的な振る舞いを実現しています。

## 🛠️ 本作の開発を通じて得た成果とデバッグ経験

* **`console.log` を使ったデータ追跡のデバッグ能力**
  `isReturning` や `failMemory` などの変数をConsoleに出力し、「AIが実際に何を考えているのか」を観察。「想定と実際の数値のズレ」から問題を論理的に絞り込む経験を積みました。
* **バグを「現象」と「原因」に分けて考えるアプローチ**
  「動かない」で終わらせず、帰還地点のログや変数を一つずつ遡り（`memo` ➔ `saveFailMemory` ➔ `isReturning`）、原因候補を自力で切り分けるプロセスを体得しました。

## 📅 今後の課題と第4作品目（RPG）への展望
本作の最終的な動作確認において、帰還後の再探索における方向決定（全方向への連動）に一部課題が残りました。

しかし、本作を「AIを完成させられなかった作品」ではなく、**「AIを自分でゼロから設計し、デバッグの深部まで踏み込んだ大きな成長の証」**と捉えています。ここで得た「データ管理の課題」や「バグの出にくい関数設計の重要性」という教訓（宿題）は、現在設計を進めている**第4作品目（総まとめとなる本格RPG開発）で100倍にしてリベンジし、完全実装を果たします。**
